# Ask once for a complete local requirement

In each of the eight archived Syria peer note pairs, use the public
clauses and endorsements admitted in the previous run. Freeze the
candidate requests before inference. Ask each speaker for their one
complete fictional requirement in a separate counterfactual branch.
The replying actor sees their own private card, the public menu and
the existing two notes. Their original system and user context is
replaced with an explicit request to report their own requirement.
Never pass the other speaker's card, joint decision or answer key.

Use one reply per branch. Admit only a completed, exact JSON object
with a field and value from the workshop dictionary. Bind it to the
speaker who was asked. A completed full requirement declares that
packages satisfying it are locally acceptable and supersedes that
speaker's earlier workshop claims. Score truth against the asked
speaker's card only after public certification. If the response is
invalid, keep the original admitted claims. The ledger receives no
private state.

Compare silence, asking the first or second speaker, a rule asking
the speaker missing a requirement, and a fitted public-state router.
Charge the same question cost. Train the router on synthetic menu
worlds with independent assumed reply erasure and no Syria prompts,
responses or labels. The primary live endpoint is supported correct
decisions, including whether the graph can certify agreement with
one question. These calls validate a bounded clarification channel
on one exposed family with frozen Qwen3.5-4B.
